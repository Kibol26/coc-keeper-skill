# LLM 状态丢失补偿模式

## 问题

LLM（包括 Hermes 用的 minimax-M3）跑**长 TRPG / 长跑团 / 长模拟**时会丢状态：

- 忘记玩家之前说过什么
- 忘记 NPC 的态度
- 忘记已经发生的剧情
- 忘记调查员当前的 HP/SAN

这不是 bug，是 LLM 的物理限制（context window + attention decay）。

## 解决方案：Clue Ledger（线索账本）

在任何长 session（> 30 分钟 / > 20 次交互）中，**强制维护 4 张表**：

1. **线索表** — 已发现 / 已解 / 未发现
2. **NPC 表** — 态度 + 位置 + 备注
3. **时间线** — 按时序列出所有重大事件
4. **状态表** — 玩家/角色的 HP/SAN/装备

## 为什么有效

- **External memory** 替代 internal memory：把信息从 LLM 的 context 移到磁盘文件
- **Bounded retrieval**：每次只需读 1 张表，不是整个 conversation
- **可审查**：玩家可以反查"我昨天发现了什么"
- **跨 session 持久**：session 结束、模型重启都能恢复

## 实现位置

放在 session 的 `data/<session_id>/session_log.md` 顶部。每次重大事件后追加，**不许省略**。

## 何时追加（trigger）

- 玩家发现新线索
- NPC 移动 / 改变态度
- 跨场景（时间推进 ≥ 1 小时）
- 玩家状态变化（受伤、SAN 损失、获得物品）
- 战斗结束
- 模组阶段切换

## 强制约束

KP / GM / DM agent 必须**每次**叙事后**自动**更新账本。这是规则，不是建议。

## 范例（节选）

```markdown
## 线索账本

| 状态 | 位置 | NPC | 备注 |
|---|---|---|---|
| 已发现 / 未解 | 阁楼 | — | 血迹从窗户延伸到墙角 |
| 已发现 / 已解 | 客厅 | Edward | 他父亲 1870 年死于"脱水性昏厥" |
| 未发现 | 阁楼暗门 | — | 需侦查 60+ 极难成功 |

## NPC 表

| NPC | 态度 | 位置 | 备注 |
|---|---|---|---|
| Edward | 紧张/隐瞒 | 客厅 | 提到父亲时回避眼神 |
| Mary | 友善/警惕 | 厨房 | 见过夜间"水妖" |

## 时间线

- 第 1 天 19:00 — Alice、Bob 抵达边境小屋
- 第 1 天 22:00 — 阁楼发现血迹（侦查 28/55 成功）
- 第 2 天 03:00 — Alice 目睹水妖（SAN check 0/1D6，大失败 → 扣 6，触发 BT）

## 玩家状态

| 角色 | HP | SAN | MP | LUCK | 状态 |
|---|---|---|---|---|---|
| Alice | 10/10 | 49/55 | 11/12 | 35 | 恐惧症：恐水症（潜伏） |
| Bob | 8/8 | 40/40 | 8/8 | 30 | 正常 |
```

## 通用化

这个模式适用于**任何需要 LLM 长时间维持状态的任务**：
- TRPG / 跑团（已用）
- 多轮模拟（如 IC2 tech tree 模拟）
- 长期项目规划（state machine + 进度账本）
- 多 agent 协同（共享 ledger 文件）

不是 TRPG 专属，是 **LLM-as-stateful-agent** 的通用补偿模式。
